## 本次范围

按当时用户确认，先修复飞书在线文档的关联和点击打开；聊天上传的 Word、Excel、PDF、HTML 等附件的 Markdown 打开／下载入口暂缓。该次修复没有增加服务端接口，也没有把文件名恢复当作附件下载修复完成。当前程序为分析而下载附件正文的内部能力，与给日报阅读者提供点击入口是两个不同范围。

原有 2026-09-29、2026-09-30 日报保持原样，不重新生成、发送、上传或覆盖。

## 根因

1. 最终文件关联再次检查总结中是否出现文档名称或 URL。文档引用已经合法，仍可能因为总结改写被删除。
2. 关联消息在多个位置丢失：来源校验只保留主要消息；全日合并只使用原始消息顺序；最后关联文件也只收到原始筛选消息。补读文档参与总结后，引用仍可能在后续步骤丢失。
3. 原来的补挂逻辑搜索全局文档或同会话附件，缺少事件来源范围的约束。
4. 附件按文件名去重，会把同名的不同上传文件合成一项。附件 URL 为空则是独立的访问能力缺口，与模型选型无关。
5. 多人汇总原来按“URL + 标题”去重，同一地址使用不同标题会重复展示；需要与个人事件采用一致的文档去重规则。

## 本地改动

- `src/worktrace/runner.py`：记录实际送入分析的消息片段，包括重试、分段和备用分析里的关联消息。后续复核、消息顺序和文件关联共用这些证据；每次运行清空记录。已选择的有效链接不再检查总结文字。直接引用和补挂均限制在该事件的来源消息中。
- `src/worktrace/pipeline/validation.py`：来源必须包含当前片段的主要消息，同时保留事件明确选作证据、且已经读取的关联消息。仅引用上下文的候选不会成为新事件。
- `src/worktrace/pipeline/conversation_segments.py`：允许当前片段的主要消息和已提供的上下文共同成为证据；仍禁止从未提供的消息或其他片段借用来源。
- `src/worktrace/analyzers/prompts.py`：同步上述来源规则，要求模型列出实际使用的上下文编号。Python 校验编号、关联文件及计算数量。
- `src/worktrace/collected_merge.py`：多人汇总按原文档地址去重，不再因不同标题重复展示；正文改写和多轮滚动合并均保留来源事件的文档链接。

文档按照原始完整 URL 去重，保留真实地址，不去掉可能影响跳转的查询参数或锚点；相同地址优先保留来源中的文档标题，空标题或直接用 URL 作标题的记录可由真实标题补齐。个人事件的附件按照附件 ID 去重，同名但 ID 不同的文件分别保留。多人汇总的无地址附件暂时沿用原有名称去重方式；本次未新增附件来源协议。现有敏感参数脱敏规则继续生效。

## 同一文件与事件合并

不同会话或不同人员引用同一文件，是同一事项的重要线索。现有 Python 逻辑会按已校验的文件标识建立关系，将这些事件放入同一复核范围；本次补读证据修复后，补读消息中的文档也能参与判断。此处认定“同一文件”的地址规则不影响 Markdown 保留原始完整访问链接。

复核仍要结合完整事件内容判断共同对象和动作联系。同一事项的排期确认、结果核对可以合并；共用公共文档但处理不同事项时可以分开。不能仅凭同名文件或同一会话自动合并。多人 Markdown 中已有的文件标识会继续经过写入、读取和滚动合并保留；已经缺失链接和标识的历史日报不会自动补回。

当前文件关系的 URL 标准化会去掉查询参数与锚点，并统一协议和主机大小写；公开点击链接仍保留完整地址结构，仅替换已知敏感参数值。文档链接保留和文件去重由 Python 处理，`codex_with_fallback`、`online_only` 两种模式沿用同一规则。模型来源编号覆盖检查不能逐句证明正文准确，文件存在也不证明不同来源一定是同一事项。

## 验证边界

## 附件入口后续方案（未实施）

历史调查中的目标项目是 `worktrace.gydev.cn`，远程 GitNexus 仓库标识为 `cos-power-web__websource__worktrace-gydev-cn`。当时远程结果列出了 `packages/server/src/dailyReportStorage.ts`、`packages/front/src/services/dailyReportService.ts`，以及随服务端分发的 WorkTrace Python 副本；这些远程源码不在本次本地核对范围，实施前需重新核对服务端当前源码。

可执行步骤：

1. 服务端登记附件来源，保存消息 ID、附件 ID 和原文件名，并返回服务端实际创建的附件记录 ID。不得在 Markdown 中保存 API Key、访问令牌或签名凭据。
2. 增加受网站登录保护的稳定打开入口。用户点击时，验证其飞书身份，并使用点击者自己的授权读取原聊天文件。不能使用日报作者或机器人的宽泛权限代替阅读者权限；若当前官方接口无法按点击者权限读取某类资源，该类附件明确不可用，不提供越权替代入口。
3. 服务端通过官方接口取得原文件，保留原文件名，按格式预览或返回下载响应。打开入口使用网站正常登录会话鉴权，不要求浏览器为飞书 OpenAPI 手工添加请求头。
4. 权限不足、资源不存在、授权过期、保密限制、文件过大或上游无法读取时，分别展示实际原因。若未来使用临时地址，应返回到期时间，并通过稳定入口重新取得地址；不能把临时地址称为长期有效。
5. 本地 Python 只在服务端返回已创建、可访问的入口后写入 Markdown。使用真实账号验证有权限和无权限访问，并核对下载文件名及文件字节，之后再验收附件入口。

当前没有实现这些接口或生成附件链接，也没有复制文件到公开存储或改变任何文件权限。
