# 个人最终核对与高推理改进验证

本轮修改作为 WorkTrace 4.1.6 发布，针对 4.1.5 的个人动作、角色、证据对应失败。只修改
WorkTrace；本轮记录不代表家庭或 Windows 的真实整日报已经通过。

## 行为

- Online 默认 `high`，只提取最终函数参数；高推理不发送 `/no_think`。
  Responses 使用 `reasoning.effort`，Chat Completions 使用
  `reasoning_effort`，文字、图片与探针一致。
- 思考模式的在线服务拒绝强制指定函数。本轮真实探针复现 HTTP 400，
  改用 `tool_choice=auto` 后通过。每次只提供一个目标函数，关闭并行
  工具调用，Python 仍拒绝空返回、错误函数、多次调用和非法参数。
  流式完成事件明确提供最终结果时，不再用早期参数片段掩盖最终错误。
- 模型在本人动作内选择多选角色；唯一角色由 Python 确定。角色直接使用
  动作证据，不再重复填写另一份角色证据。事实不再填写动作编号，程序
  根据共同证据建立关联；允许事实使用动作证据的相关子集。
- 旧格式仍可读取，旧动作编号按证据重新计算；新旧角色格式不能混用，
  防止旧字段把明确选择的协作升级成主责。未知证据、他人证据冒充本人、
  多选角色不兼容、本人动作或锁定成员未覆盖仍会失败。
- 当前组的重试携带上一份完整返回和具体错误，并计入输入估算。没有
  增加重试次数或输入预算。未解决的最终错误仍使本次生成失败；CLI
  普通重跑保留旧日报，新报告生成成功才替换，也不发送失败结果。

## 已验证

- macOS / Python 3.13：完整离线套件 1051 通过、24 跳过，0 失败。
  其中包含个人、多人的流程、安全诊断、旧报告保护及文档检查。
- 独立代码审查已完成。真实 SDK 的离线 HTTP 序列化核验覆盖两接口的
  文字和图片请求；均发送 high。流式和非流式都不把思考文本作为事件。
- 本机既有在线服务：固定高推理探针通过；合成“同事交付、本人接收”
  案例使用实际个人最终核对流程，一次请求通过，0 重试、0 失败，角色
  为回应。未读取飞书聊天、写入正式日报或发送消息。
- 家庭环境已有的 10 份原始模型返回仅在本地离线复核。Python 重算：
  发布代码通过 4 份，修改后通过 9 份；按各组最后一次返回计算，通过
  组数从 4/6 变为 5/6。剩余旧返回的多选角色仍与动作证据不符。新输出
  已把角色移入对应动作，需要通过重新生成验证，不能把旧返回回放说成
  家庭整日报验收通过。私有输入和模型返回没有加入仓库。

新默认值不会覆盖已有设置。Codex 继续使用其独立的本地推理设置。
